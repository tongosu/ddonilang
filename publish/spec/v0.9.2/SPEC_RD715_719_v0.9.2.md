# RD-715~719 공개 후속 규범

이 문서의 효력은 [판본 명세](SPEC_MANIFEST_v0.9.2.md)와 공개 CURRENT를 따른다. v0.9.1의 기존 규범·실패·기술 OPEN·UNKNOWN·NOT_RUN을 계승하며, 아래 명시 범위만 좁은 후속으로 읽는다. 내부 v25.156.0의 RD715~719 의미를 v25.157.0의 구조에서 재투영한 것이며 157은 새 의미판이 아니다. 문서 규범은 제품 지원·새 예제 실행·Human·배포 판정과 별개다.

## RD-715 — 명시 모형의 고정 RK4 시간 연결

기존 `풀기`의 `푸는법` 받는자리와, 생략하면 항상 `#정밀`인 정확·비순환 경로를 유지한다. 명시 `푸는법`에 결속한 SolveRecipe의 `방식:#고정RK4`, `간격`, `내줌간격`으로 첫 시간 연결을 선택할 수 있다. 바깥 받는자리 `푸는법`, recipe 내부의 `방식`, 표준 라이브러리의 개별 수치풀이 callable은 서로 다른 층이다. 옛 `방법=`은 현행 alias가 아니다. 다른 방법의 자동 선택·대체·실패 후 fallback은 허용하지 않는다.

RK4 알고리즘과 Fixed64 Q31.32 연산·평가 순서·roundTiesToEven·실패는 기존 RD589/590을 재사용한다. per-call numeric profile이나 새 공개 solver Definition/ProviderIdentity를 이 조항이 발급하지 않는다. RD607의 수치풀이 callable과 모형 SolveRecipe를 동일시하지 않는다.

계산 시작·끝과 관찰 표본은 계산 격자에 정확히 놓여야 한다. 내줌간격은 계산 간격의 정수 배이며 맞지 않는 끝·관찰 간격은 거부한다. 마지막 스텝 단축·보간·숨은 허용오차·시간축 단위 추정을 하지 않는다. 종단 스칼라와 실제 선택된 모델 표본을 구별하고, 명시 내보임은 공급된 각 표본에서 평가한다. 종단 스칼라를 반복해 계열을 만들거나 UI 행을 추정 결합하지 않는다.

선택된 모델 표본은 후보 검증이 끝난 뒤 원자적으로 공개한다. 검증 전 관찰·완료를 공개하지 않는다. 처음받음·원문·들임·풀이 방법·판본은 기존 모형 소유와 실행 계약에 결속한다. 저장은 기존 원문·조건만 보존하며 재열기가 궤적이나 보임을 복원하지 않는다. 재열기 뒤에는 명시한 새 실행이 필요하다. 새 저장 schema나 세계 resume 계약을 추가하지 않는다.

첫 범위는 승인된 직접 1차 시간 모형 연결이다. RD194의 기존 정확 경로 밖에 이 명시 연결만 추가한다. 일반 DAE·암묵 순환·자동 2차식 재작성·사건 reset/재초기화·흘러드는 입력·adaptive 방법은 추가하지 않으며 RD195의 나머지 비지원도 유지한다. profile·실물 등록·정확 AST·진단 공급은 기술 OPEN이다.

## RD-716 — 닫힌 두 갈래 카드의 두 호출 등식 목표

이름 있는 보임 셈씨의 결과 씨 `(왼쪽 =:= 오른쪽)보임`에서 양변 각각 하나의 명시 핀 호출을 받는다. 첫 범위의 카드 씨는 실제로 해소된 닫힌 두 갈래 선언이다. 두 호출은 같은 머리의 `면:카드` 받는자리를 전달하고 각각 유일하게 해소된 실제 `카드 → 카드` 셈씨를 가리킨다. 실제 정의·소유 핀·원문 판본을 보존하며 표시 이름·문자열·구조적 유사성으로 다른 선언을 합치지 않는다.

결과 씨의 `면` 참조는 기존 머리 binder 결속을 재사용한다. 목표는 카드 선언·두 갈래·공통 받는자리·왼쪽/오른쪽 Definition과 Pin·각 의존 판본에 결속된다. 마지막 함수 본문 한 줄이 다른 정상/반례는 서로의 정의 판본을 재사용하지 않는다. 진단 span은 실제 SourceSnapshot과 함께 보존한다.

정상과 반례 모두 같은 목표 작성·해소 관문을 통과해야 한다. 거짓 목표라는 이유로 파싱·해소를 다르게 하지 않는다. 그 뒤 checker의 참거짓 판정은 별도이며 목표 해소 자체는 보임·검사된 반증 발급이 아니다. RD308/314/421/423의 증거·검사 권위를 유지한다. 일반 고름씨 확대·일반 셈씨 투명성·임의 계산식 전체의 목표 허용은 추가하지 않는다. 실제 parser·typed 표현·목표 해소 연결은 제품 구현 접점이다.

## RD-717 — 시작 칸의 canonical 정의 참조

시작 칸은 정의한 canonical 이름을 그대로 참조한다. RD524의 로컬 모듈 소유 executable DefinitionIdentity와 기존 함수값·호출·invocation-local ResultPlace의 구분을 재사용한다. 참조의 해소는 호출이 아니다. 철자에서 `기/하기`를 제거해 정의를 찾거나 새 참조 alias를 만들지 않는다.

해소가 0개·복수이거나 기존 executable 조건을 위반하면 실행 전에 거부한다. 새로운 무인자 움직씨-only 제한이나 옛 호출 꼴에 대한 새 강제 교정 진단을 이 조항에서 추가하지 않는다. 정확 기존 시작 admission과 저장된 alias의 실제 손실은 원전 대조·기술/호환 공급 대상이다. 과거 저장 원문·판본을 자동 rename·재발급하지 않는다.

## RD-718 — 선택된 시작 본문과 훅 소유

단일 원문의 root와 모둠에서 명시 선택한 시작 정의 본문을 각각 실행의 진입 단위로 다룬다. RD709의 새 의미 실행 첫 실제 마디에서 시작 1회·첫 마디 포함 매마디·보통 문장과 훅의 원문 순서를 선택된 본문에도 적용한다. hoist·별도 phase·자동 재배치·중복 등록을 만들지 않는다.

실행마다 진입은 한 번이고 훅도 한 번 등록된다. 저장 재열기·continue·같은 실행의 새 기록구간은 시작 재발동 0이다. 격리된 원 씨앗 재생은 원 계산의 재현이며 원 세계에 효과를 추가 공개하지 않는다. body 완료와 마디 전체 성공 공개·기존 실패/복구는 구별한다.

훅을 담은 시작 정의의 일반 호출과, 시작 정의가 아닌 정의 안의 훅은 거부한다. 훅 없는 일반 움직씨 호출 전체는 금지하지 않는다. 모둠 머리 top-level 실행문과 선택 시작 본문의 공존 Q4는 OPEN이다. 임의 hoist나 두 번째 진입으로 메우지 않는다. 이 미확정 slice만 분리하고 단일 root 및 top-level 공존을 요구하지 않는 시작 본문 계약을 먼저 적용한다. continuation carrier/schema·실제 lifecycle 연결은 기술 OPEN이며 새 저장 뜻을 발급하지 않는다.

## RD-719 — 명시 줄기와 첫 기 꼴의 유한 전개

새 후속 한국어 규약의 `{…}`는 완성형 전체집합이 아니라 작성자가 명시한 변형 줄기 집합 S다. canonical 이름 C에서 `B={C}∪{끝 다를 한 번 뺀 C: 다로 끝날 때}∪S`이고, 생성 꼴은 각 바탕에 선택적 `하`와 고정 판본의 닫힌 어미를 붙인다. 품사·자연스러움·형태소 역추정으로 꼴을 추가하거나 제거하지 않는다. 같은 정의에서 중복 철자는 집합 하나이며 다른 정의의 소유를 합치지 않는다.

이번 후속판의 닫힌 어미는 RD714가 고정한 첫 `E={기}`뿐이다. 고/면/며/면서 등 전체 목록과 조건·반복·연결 실행 의미는 추가하지 않는다. RD714의 중괄호 없는 첫 규약은 유지하고 새 줄기 입력은 후속 규약의 정확 판본·등록에만 결속한다. 예시 몇 개를 전체 accepted-set으로 축소하지 않고 집합을 완전 전개한다.

RD326/408/570/712의 구 full-form 작성 의미는 새판 줄기 입력의 해당 범위에서만 부분 대체한다. RD570의 자연어 비권위·유한 exact 등록/소유 원칙, 다른 말씨, 기존 scope·가림·유일해소·입증된 disjoint overload는 유지한다. RD714의 ResultPlace·함수값·무인자·단일평가 경계도 바꾸지 않는다. generated form은 ResultPlace·bare 함수값 alias가 아니며 순수 바탕을 자동 무인자 호출로 읽지 않는다.

구판 explicit full-form과 새 줄기를 같은 의미로 보지 않는다. 구판 원문/profile bytes를 소급 해석하거나 열기·저장만으로 전환하지 않는다. 실제 손실이 나오면 정확 원문·기존/새 집합·소유/해소 영향·최소 이행을 반환한다. 전체 교재/Q12 전수를 첫 좁은 단위의 선행조건으로 삼지 않는다. 실손실의 구체 이행 선택과 exact profile/등록·구문·진단 공급은 OPEN이다.
