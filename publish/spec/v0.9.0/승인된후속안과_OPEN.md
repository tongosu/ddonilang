## 선언된 나

승인된 범위: F1-A는 지정 호출 결과의 바깥 맺음 안됨 갈래 전체만 거부하고, F2-A는 실행 전에 직접 소유 호출·기존 미공개 실패 경계·바깥 공개 owner를 명시 결속한다. 무조건 typed 실패 전파·자동 rollback으로 확대하지 않는다. 정확 작성 문법·typed 공급·IR/기록·실행/저장·검증은 OPEN이다.

승인 원문: 「좋아. 선언된 나·실패경계 연결 후보 R1.1 묶음 채택을 승인할게. ssot와 기획에 전달하고 정본 승격·제품 착수는 별도 절차로 두자. 환급은 R1-A, R2-A, R3-A로 가고, 승인된 의미와 남은 기술 과제를 분리해 정리해줘.」

## 미결 목록과 진입 경계

- 화살표 기계 정규형: 미결. 양방향 의미 방향 승인을 `<-` 또는 `->` machine canon 채택으로 확대하지 않는다.
- A{A} 정확 DDL 문법·중괄호 생략: OPEN. 명시 {A} 공급의 논리 요구와 현재 제품 중복 거부를 구분한다.
- 일본어 어휘·판본별 등록·원어민 검토: OPEN. 계획의 채택이 어휘 최종 선정이나 등록 완료가 아니다.
- 일반 복구 블록 RHS·첫 결속·합류 값: 후속. 세금 예제는 문장형 에 따라를 사용한다.
- 미등록 EXE 이름 정책: 후속. トニラン.exe 표시 기본값 계획과 별개다.
- 되감기 근사 비교: 후속. 정확 비교 설계의 기술 OPEN을 유지한다.
- V2 미리보기 공개: V1 마감 뒤 별도 판단. 기능별 공식 예제·첫걸음 설명 완료 조건은 승인된 계획으로 유지한다.
- 한국어 세금: dev 신규 작성·검증 착수 승인 있음. 실제 baseline·활성 writer·hunk 확정, 실제 본문·공개 핀·정체·의존 공급과 CLI/WASM 검증은 완료 미확인이다. 공통 제품 변경은 이 SPEC 과업에 포함되지 않는다.
