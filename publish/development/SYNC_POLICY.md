# 변경 결과의 발행과 원격 확인

정본·결정·검토 결과와 의미 있는 고정 변경을 반영할 때 필요한 저장소·협업 공유의 갱신과 원격 확인을 같은 작업의 완료 조건으로 관리합니다. 임시 편집마다 재발행하거나 감시·예약을 만드는 정책은 아닙니다.

- 공개 저장소에는 공개 승인·권리/라이선스·민감도·검토 경계를 통과한 코드와 공개 문서만 반영합니다. 비공개 원문·인증정보·개인/고객자료·진행 중인 변경을 자동 공개하지 않습니다. 공개 조건이 확인되지 않은 코드 대신 허용된 요약을 제공하고 제외 이유를 기록합니다.
- 진행 중인 작업과 기존 기록을 보존하며 과업에 속하는 최소 변경만 다룹니다. 전체 변경을 한꺼번에 stage하거나 reset/clean·강제 push·이력 재작성으로 덮어쓰지 않습니다. 고정 자료의 보관과 실제 제품 통합은 구분합니다.
- 변경 전 백업과 별도 복원 대조, 고정 원문/판본·파일별 해시 확인을 거칩니다. 공유 자료를 먼저 검증하고 안정 진입점을 마지막에 전환합니다.
- 게시 뒤 원격 commit/tree/작성자와 변경 파일 전체의 blob 정체 또는 원문 해시를 확인합니다. 협업 공유도 변경 파일 전체의 서버 원문을 대조하며 파일 시각·메타데이터·일부 표본을 전체 확인으로 확대하지 않습니다.
- 로컬 발행, 저장소 원격 반영, 공유 서버 동기화, 실제 AI 열람 상태를 분리합니다. 필요한 확인이 남으면 미완 범위·이유·다음 행동을 기록하고 전체 완료라고 보고하지 않습니다.

이 운영 원칙은 새 코드의 공개 적합성, 제품 지원, 독립검토·Human PASS, 언어 정본 승격 또는 Release/배포 승인을 대신하지 않습니다. 내부 문서 v25.155.0과 공개 SPEC v0.9.0의 규범 범위도 유지합니다. 변경이 없는 면은 이유를 기록하고 불필요한 커밋·재검사를 생략합니다.

정책 적용일: 2026-11-01. 사람 저자·커미터와 AI를 사용한 개발 사실은 구분합니다.
