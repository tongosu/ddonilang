# 베타3 직접 확인 순서

내부 개발 후보입니다. 아래 목록이 있다는 뜻과 실제로 통과했다는 뜻은 다릅니다. 직접 해 보신 항목만 통과로 알려 주세요. 이전 저장본과 기록은 지우지 않습니다.

1. ZIP을 새 폴더에 풀고 `START_SEAMGRIM.cmd`를 실행합니다. 작업대가 열리고 공식 모음의 작품을 실행할 수 있어야 합니다.
2. **공식 모음 → 테트리스 → 상단 저장**을 누릅니다. ‘내 작업으로 저장했습니다’와 Native 확인 안내가 나와야 합니다. 처음 저장할 때 새 ID를 만들며, 다시 저장하면 그 ID를 유지합니다. 입력 계약과 키 배치도 함께 연결되므로 JSON을 직접 넣지 않고 ▶·방향키로 움직인 뒤 일시정지합니다. 저장 전 ▶를 먼저 누르면 ‘내 작업에 저장하고 실행’ 확인이 나오며 취소하면 저장·실행하지 않습니다. Native에서는 이미 검증된 `root.ddn`·`main.ddn` 프로젝트 원문을 그대로 사용합니다. 한 파일을 화면에서 몰래 바꾸지 않습니다.
3. 한 마디 단추로 대기 키 입력까지 처리한 뒤 상단 **저장**을 누릅니다. **현재 논리 세계를 Native에 저장**했다는 안내를 기다립니다. ‘더 보기 → 입력 기록과 계약’에서 **기록 마치기·저장**을 누릅니다. 마지막으로 성공한 마디까지 기록 파일이 내려받아져야 합니다. 대기 중인 입력이 있었다면 제외 개수 안내가 나와야 하고, 없었다면 제외 안내는 나오지 않습니다.
4. 입력 기록 창의 **고급 설정 → 저장한 완료 기록 재현 확인**을 누릅니다. ‘재현 확인’이 나오고 현재 판과 마디는 그대로여야 합니다. 오류가 나오면 그 문구를 그대로 알려 주세요.
5. 작업대와 실행 창을 닫았다 다시 시작합니다. **내 작업 → 테트리스(Native 저장)**를 누릅니다. 저장 원문과 정체는 Native에서 다시 확인하고, 목록에 기억한 입력 계약도 현재 원문에 다시 결속합니다. **더 보기 → 입력 기록 → 고급 설정 → 저장한 완료 기록 재현 확인**을 누르면 원래 저장한 결과와 같아야 합니다. 새 작품을 만들거나 처음부터 실행해서 대신하지 않습니다. 내 작업 목록은 저장 위치 안내이지 실행 권한이나 세계의 근거가 아닙니다.
6. **저장한 시점에서 새 기록**으로 이어 실행하고, 이번에는 **미완 기록으로 중단·저장**합니다. 중단 기록을 정상 완료 재생으로 받아들이지 않고 이유를 알려야 합니다.
7. **⇧ 가져오기**로 ZIP의 `solutions/seamgrim_ui_mvp/samples/beta1_logical_counter/authored-project.json`을 엽니다. 폴더 이름에 logical이 있지만 이 단계에서는 입력 계약을 결속하지 않고 일반 실행으로 확인합니다. 먼저 상단 **저장**으로 작성 자료를 Native에 저장하고, ▶ → 일시정지 → **저장** 순서로 실행 상태를 저장합니다. **더 보기 → 작성 정체 자료 → 저장 결과 대조**를 누릅니다. 저장 시점의 세계와 출력이 일치한다는 안내와 ‘정상 종료 영수증 확인은 아닙니다’라는 구분이 나와야 합니다. 창을 닫고 한 마디 더 실행·저장한 다음에도 같은 대조를 할 수 있어야 합니다. 공식 모음의 임시 저장으로 대신하지 않습니다.
8. 일반 작품도 실행 창과 브라우저를 닫았다 다시 열어 저장 자료를 읽고 **저장 결과 대조**를 누릅니다. 새 실행을 시작하지 않고 저장된 결과가 확인되어야 합니다. 원 기록이 없는 옛 저장본은 임의로 새 증거를 만들지 않고 거부합니다.

## CLI로 기록 확인하기

2번에서 저장한 작품의 **더 보기 → 작성 정체 자료 → 새 버전 저장 구간(읽기 전용)**에 보이는 JSON 전체를 복사하여 UTF-8 파일 `내작품.json`으로 보관합니다. 이는 표시된 원문 자료를 복사하는 것이며, Native 권한이나 영수증을 내보내는 것이 아닙니다. 입력 기록의 고급 설정에서 현재 결속된 입력 계약 JSON도 `입력계약.json`으로 보관합니다. Native 작성 자료의 자동 내보내기는 아직 지원하지 않습니다. 새 ID로 저장한 작품을 ZIP 예제의 다른 ID로 대체하거나 원문 한 파일만 발췌하지 않습니다.

새 ZIP 폴더의 터미널에서 실제 내려받은 완료 기록을 재생합니다. 아래 경로는 방금 보관한 동일한 작성 자료·기록·입력 계약의 위치로 바꿉니다.

```powershell
.\bin\ddonilang.exe logical-replay .\내작품.json .\완료기록.bin .\입력계약.json --authored
```

`ddonirang.exe`, `또니랑.exe`로 바꿔도 결과가 같아야 합니다. 이것은 완료 입력 기록의 실행 결과 대조이며, Native 저장 영수증의 권한 검증은 위 작업대 절차로 따로 확인합니다. 다른 원문·손상 기록·미완 기록은 이유를 붙여 거부해야 합니다.

## 아직 구분해야 하는 것

- 기록 마치기 도중 실행 창이 닫혀 완료 확인이나 새 기록이 거부되면, 기존 저장본과 기록을 지우거나 덮어쓰지 마세요. 안내는 완료·이어 실행을 확인하지 못했다는 뜻이며 자동 복구가 아닙니다. 원문만 새 작품으로 시작하려면 입력 기록 창을 닫고 **더 보기 → 작성 정체 자료 → 새 ID로 복제 → 저장**을 선택합니다. 이전 진행·완료 기록이 복구되거나 새 작품으로 옮겨지는 것은 아닙니다. 실제 중단 복구는 내부 정리 단계의 후속 과업입니다.

- **Native 공식 모음 테트리스는 명시 저장 때 내 작업이 됩니다.** 모음을 열기만 해서는 영구 정체나 저장 권한을 만들지 않습니다. Native가 없는 정적 서버에서는 기존 한 파일 실행·브라우저 임시 저장으로 남으며 Native 영수증 확인으로 표시하지 않습니다.
- 같은 예제 ID로 다른 원문이 이미 저장돼 있으면 덮어쓰지 않고 거부합니다. 저장되지 않은 편집을 따로 보관한 뒤 마지막 저장 자료를 다시 열거나, 예제 파일을 다시 가져와 작성 자료 창의 **새 ID로 복제**를 명시적으로 누르고 저장하세요. 처음부터 별도 작품으로 시작하려면 2번에서 파일을 가져온 직후 먼저 새 ID로 복제합니다.
- 화면은 0부터 세는 **마디 번호**이고, ‘마디 4까지(5마디)’의 괄호 안은 처리한 **개수**입니다.
- 일반 작품의 저장 결과 대조는 진행 중 저장 경계의 비교이며 정상 종료 영수증이 아닙니다.
- 원자 출력은 실제 원문 등록 증거에 결속된 출력 전용 형식으로 확인합니다. 원자를 글로 바꾸거나 새 저장용 타입을 허용하는 방식은 아닙니다.
- 작업대 원 기록 전송은 8MiB까지입니다. 넘는 기록은 잘라서 성공시키지 않습니다.
- 이 목록은 전체 베타3 완료, 독립검토, 공개 승인 또는 사람의 사용 확인을 대신하지 않습니다.
