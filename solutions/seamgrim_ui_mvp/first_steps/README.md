# 정의 중심 또니랑 첫걸음 10차시

작은 계산 규칙을 셈씨로 정의하고, 조사로 호출하며, 진행과 출력은 움직씨로 작성하는 입문 코스다. 1차시는 몸풀기이고 2차시부터 끝까지 **정의하고 부른다**는 같은 틀로 배운다. 조건·반복·차림은 정의 본문 안에서 익힌다.

본문 예제는 40개다. 정상35개와 의도한 오류5개로 구성하며 오류를 고친 실행 예제5개와 차시별 대표 수정실습10개를 별도로 제공한다. 보충 원문2개까지 총57개이며 정상 실행 대상은52개, 거부를 확인하는 대상은5개다. 의도한 오류는 07D_핀중복오류와 08A부터08D까지다. [교사용 안내와 해답](교사용_안내와_해답.md)도 함께 읽는다. 기존 R5 묶음과 R3·R3.1은 보존했다. 이 코스는 현재 제품에 맞춘 새 수업본으로, 옛40개를 그대로 이관했다고 주장하지 않는다.

## 실행과 읽는 방법

각 차시는 설명을 읽고, 예상 값을 써 보고, 원문을 실행하고, 값을 바꾼 뒤 이유를 설명하는 순서다. 예상 답을 먼저 보지 않으려면 교사의 안내를 따라 예제 파일부터 읽는다.

CLI 실행 파일이 있는 폴더에서 이 코스 파일의 실제 경로를 넣어 실행한다. PowerShell에서는 현재 폴더의 실행 파일 앞에 `.\`를 붙인다. 아래 명령의 경로는 자신이 저장한 코스 경로로 바꾼다.

```powershell
.\또니랑.exe 실행 "코스경로\예제\02A_두배정의.ddn" --source-profile v1-core-v25 --마디수 1
```

셈그림의 **첫걸음** 메뉴에서 활동을 골라 실행한다. 작업 도구의 **학습 안내**를 누르면 옆 패널에서 학생용 PDF와 **이전 활동·다음 활동**을 열 수 있다. **먼저 예상한 뒤 결과·해설 확인**을 펼쳐 답을 대조한다. 원문을 직접 고쳐 실행하고 저장·재열기할 수 있다. 각 예제는 한 번 실행하며, `매마디` 실행 틀을 사용하지 않는다.

## 정의와 호출의 기본 모양

```ddn
(값:수~의) 두배:수:셈씨 := {
    두배 <- 값 * 2.
}.
실행:움직씨 := {
    답:수 := 7의 두배.
    답 보여주기.
}.
() 실행하기.
```

첫 정의의 받는자리는 `값`, 씨는 `수`, 조사는 `의`이다. `두배 <- ...`는 호출 결과자리에 값을 놓는다. 마지막 줄은 학생이 만든 실행 움직씨를 직접 호출한다. 한 파일 실습에는 작품 뿌리 `얽음`이 없어도 된다. 여러 모듈 프로젝트의 시작 정의와 연결하는 것은 이후 단계다.

셈씨 호출에 `하기`를 붙일 필요는 없다. 계산 결과를 가리키는 이름은 그대로 쓴다. 조사형 호출에는 인자 묶음 괄호가 필수가 아니어서 `7의 두배 보여주기.`처럼 쓸 수 있다. 반면 밑변·높이처럼 서로 다른 역할을 가진 값은 `(밑변=8, 높이=5) 삼각형넓이 보여주기.`처럼 이름 핀으로 뜻을 밝힌다. 숫자마다 조사를 억지로 붙여 `8을 5와 삼각형넓이`를 좋은 문장처럼 가르치지 않는다.

이 코스에서는 셈씨는 결과 이름으로, 움직씨는 `실행하기`·`기록하기`처럼 행동을 나타내는 호출로 구분해 연습한다. 이름의 꼬리가 셈씨·움직씨를 결정하는 것은 아니며, 선언의 `:셈씨`·`:움직씨`가 종류를 정한다. 정의의 받는자리 괄호, 이름 핀 묶음 괄호, 복잡한 식을 묶는 괄호는 조사형 호출의 선택적인 괄호와 구별한다.

## 1차시 값과 이름

먼저 수와 글을 출력한다. 같은 계산에 이름을 붙이고 보통 결속을 바꾸어 본다. `:=`는 정의를 만들고 `<-`는 결속과 다시결속을 맡는다. 처음에는 반드시 `:=`를 써야 한다고 가르치지 않는다.

예상 질문: 800원짜리 물건을 3개, 4개 사면 각각 얼마인가?

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 01A | [첫계산](예제/01A_첫계산.ddn) | 7 |
| 01B | [글과수](예제/01B_글과수.ddn) | 안녕 / 24 |
| 01C | [이름붙이기](예제/01C_이름붙이기.ddn) | 2400 |
| 01D | [결속바꾸기](예제/01D_결속바꾸기.ddn) | 3200 |

수정 활동: 01C의 개수를 4로 바꾸고 01D와 같은 3200인지 확인한다.

해설: 01D는 `<-`로 처음 결속하고 같은 이름을 다시 결속한다. `:=` 정의 이름의 다시결속 여부를 이 활동으로 확정하지 않는다.

## 2차시 셈씨 정의와 조사형 호출 및 이름 인자

받는자리의 이름·씨·조사를 선언하고, 셈씨 이름의 결과자리에 계산값을 놓는다. 조사는 값이 어느 받는자리로 가는지를 나타낸다.

예상 질문: 두배의 결과자리 이름과, 삼각형넓이의 받는자리 두 개를 표시한다.

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 02A | [두배정의](예제/02A_두배정의.ddn) | 14 |
| 02B | [이름인자로부르기](예제/02B_조사바꾸기.ddn) | 18 |
| 02C | [두받는자리](예제/02C_두받는자리.ddn) | 20 |
| 02D | [이름핀](예제/02D_이름핀.ddn) | 24 |

수정 활동: 02A의 7을 9로 바꾸고 02B와 대조한다. 02C의 높이를 6으로 바꾸고 02D와 대조한다.

해설: 02A는 `7의 두배`, 02B는 `(값=9) 두배`로 부른다. 02A의 값을9로 바꾸면 두 호출 모두18이다. 02C·02D는 밑변·높이를 이름으로 분명하게 지정하고, 이름 핀의 순서를 바꾸어도 같은 받는자리로 간다는 것을 배운다. 조사형과 이름 핀은 같은 받는자리를 명시하는 두 방법이지만, 문법상 가능하다는 이유만으로 어색한 조사를 좋은 표현으로 가르치지 않는다.

### 조사형과 이름 인자 비교

아래 두 줄은 같은 `두배` 정의에 같은 값7을 보낸다. 결과는 둘 다14다.

```ddn
7의 두배 보여주기.
(값=7) 두배 보여주기.
```

| 방식 | 소리 내어 읽기와 선택 기준 |
|---|---|
| 조사형 `7의 두배` | “7의 두 배”처럼 자연스럽고 역할이 분명할 때 쓴다. 이 호출의 인자 괄호는 필수가 아니다. |
| 이름 인자 `(값=7) 두배` | “값에7을 넣어 두 배를 구한다”로 읽는다. 받는자리 이름을 직접 지정하며, 이름 인자 묶음의 괄호는 쓴다. |

밑변·높이는 역할이 다르므로 `(밑변=8, 높이=5) 삼각형넓이`로 명시한다. 왼쪽·오른쪽처럼 대등한 두 값도 `(왼쪽=8, 오른쪽=5) 큰값`으로 대칭적으로 적는다. 한쪽에 `을`, 다른 쪽에 `와`를 억지로 붙이지 않는다. 이름 인자는 조사형보다 낮은 단계가 아니라, 뜻을 분명하게 쓰는 또 하나의 방식이다.

이름 핀을 쓰는 정의는 `(밑변:수, 높이:수) 삼각형넓이:수:셈씨 := { … }.`처럼 받는자리 이름과 씨를 선언한다. 이 예제에 억지로 조사 별칭을 붙이지 않는다. 조사의 모호함을 배우는 의도한 오류 예제 08D는 정상 작성법과 구분한다.

## 3차시 움직씨 실행과 셈씨의 차이

학생이 `실행:움직씨`를 직접 정의하고 `() 실행하기.`로 부른다. 그 안에서 계산 셈씨와 출력 움직씨를 함께 쓴다. 정의만 있는 것과 실제 호출하는 것을 구분한다.

예상 질문: 03C에서 두배를 계산하는 줄과 기록 동작을 하는 줄을 각각 찾는다.

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 03A | [실행정의](예제/03A_실행정의.ddn) | 14 |
| 03B | [직접만든움직씨](예제/03B_직접만든움직씨.ddn) | 7 / 9 |
| 03C | [계산과동작분리](예제/03C_계산과동작분리.ddn) | 14 |
| 03D | [계산만남기기](예제/03D_계산만남기기.ddn) | 출력 없음 |

수정 활동: 03C에서 기록 호출만 지우면 03D처럼 아무것도 출력하지 않는지 확인한다.

해설: 움직씨는 결과가 없는 함수라는 뜻이 아니다. 이 수업의 기록 움직씨는 결과 없는 출력 동작으로 작성했다. 결과 있는 움직씨와 게시 실패 규칙은 별도 심화 범위다.

## 4차시 정의 안에서 조건 배우기

큰값 셈씨의 두 갈래가 모두 결과자리에 값을 놓는다. 조건과 결과자리 배정은 셈씨 본문 안에 있고, 실행 움직씨는 여러 입력으로 같은 셈씨를 부른다.

예상 질문: 8과5, 3과9, 같은5, -2와-5에서 어느 갈래가 실행되는가?

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 04A | [조건의참갈래](예제/04A_조건의참갈래.ddn) | 8 |
| 04B | [조건의거짓갈래](예제/04B_조건의거짓갈래.ddn) | 9 |
| 04C | [같을때](예제/04C_같을때.ddn) | 5 |
| 04D | [음수비교](예제/04D_음수비교.ddn) | -2 |

수정 활동: 04A의 두 값을 맞바꾸어도 큰 값8이 나오는지 확인한다. `>=`를 `>`로 바꾸면 같은 값 사례는 어느 갈래로 가는가?

해설: 같은 두 값에서는 갈래가 달라도 출력은 같을 수 있다. 결과만 보고 어느 갈래였는지 추측하지 않고 조건식을 따라 설명한다.

## 5차시 정의 안에서 반복 배우기

1부터 끝수까지 더하는 누적합 셈씨의 차례와 합계는 지역 보통 결속이다. 반복 안에서 바꾸고, 반복이 끝난 뒤 셈씨 결과자리에 한 번 놓는다.

예상 질문: 끝수5는15, 끝수3은6, 끝수0은0, 끝수1은1이다. 각각 몇 번 반복하는가?

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 05A | [정의안반복](예제/05A_정의안반복.ddn) | 15 |
| 05B | [반복범위바꾸기](예제/05B_반복범위바꾸기.ddn) | 6 |
| 05C | [처음부터거짓](예제/05C_처음부터거짓.ddn) | 0 |
| 05D | [한번반복](예제/05D_한번반복.ddn) | 1 |

수정 활동: 05A의 끝수를3으로 바꾸어05B와 대조한다. 차례 증가 줄을 지우면 왜 끝나지 않을지 실행 전에 설명한다.

해설: 무한 반복을 확인하려고 실제로 실행할 필요는 없다. 종료 조건과 차례 증가의 관계를 먼저 읽는다. 세계의 매마디와 본문 내부 반복을 혼동하지 않는다.

## 6차시 정의 안에서 차림과 순회 배우기

차림을 셈씨 받는자리로 넘겨 합을 계산한다. 움직씨 안의 순회에서는 셈씨로 각 원소를 계산한 뒤 기록 움직씨를 호출한다.

예상 질문: 차림[2,4,6]의 합12와 차림[1,3,5,7]의 합16을 손으로 구한다.

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 06A | [차림받는자리](예제/06A_차림받는자리.ddn) | 12 |
| 06B | [차림바꾸기](예제/06B_차림바꾸기.ddn) | 16 |
| 06C | [한원소차림](예제/06C_한원소차림.ddn) | 5 |
| 06D | [순회와움직씨](예제/06D_순회와움직씨.ddn) | 2 / 4 / 6 |

수정 활동: 06D의 값을 차림[2,4,6]으로 바꾸면 출력은4,8,12다. 06C의 원소5를9로 바꾸면 합9다.

해설: `값들마다` 본문에서 `값들`은 현재 원소다. 본문 밖 차림 전체와 구분한다. 빈 `차림[]`의 본문 생성은 현재 제품 파서가 거부하므로 정상 지원으로 가르치지 않는다.

## 7차시 계산 규칙 연결하기

사용량·기본요금·단가로 원요금을 계산하고, 그 결과를 할인 셈씨의 받는자리로 전달한다. 실행 움직씨가 순서를 구성한다.

예상 질문: 원요금1000+120×15=2800, 할인 후2800×0.75=2100이다.

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 07A | [요금규칙연결](예제/07A_요금규칙연결.ddn) | 2800 / 2100 |
| 07B | [규칙값수정](예제/07B_규칙값수정.ddn) | 2500 / 1875 |
| 07C | [할인경계](예제/07C_할인경계.ddn) | 2800 |
| 07D | [핀중복오류](예제/07D_핀중복오류.ddn) | 거부: 중복 |

수정 활동: 07A의 사용량을100으로 바꾸어07B의2500,1875와 대조한다. 할인율0으로 바꾸어07C와 대조한다.

해설: 07D는 같은 핀에 두 값을 보낸 의도한 오류다. 뒤에 쓴 값으로 조용히 덮지 않는다. 교정예제/FIX07D_핀중복고치기.ddn을 실행해2800인지 확인한다.

## 8차시 정의 관련 오류 읽고 고치기

씨 불일치, 받는자리 누락, 결과자리 미배정, 조사 모호를 구분한다. 실제 출력에 맞춰 오류 의도를 바꾸지 않는다.

예상 질문: 각 파일이 어느 정의와 어느 호출에서 잘못되는지 실행 전에 찾는다.

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 08A | [씨불일치](예제/08A_씨불일치.ddn) | 거부: E_RUNTIME_TYPE_MISMATCH |
| 08B | [받는자리누락](예제/08B_받는자리누락.ddn) | 거부: E_CALL_REQUIRED_PIN_MISSING |
| 08C | [결과자리누락](예제/08C_결과자리누락.ddn) | 거부: E_RESULTPLACE_UNASSIGNED |
| 08D | [조사모호](예제/08D_조사모호.ddn) | 거부: 모호 |

수정 활동: 교정예제의 FIX08A부터 FIX08D까지 차례로 실행한다. 오류 원문과 바뀐 한 부분을 비교한다.

해설: 씨 오류는 수7 전달, 핀 누락은 높이5 추가, 결과 누락은 결과자리 배정, 조사 모호는 이름 핀으로 명시해 고친다. 계산식 자체를 다른 문제로 바꾸지 않는다.

## 9차시 용사와 슬라임 그리고 미로의 열쇠

피해와 남은체력, 문판정을 각각 셈씨로 정의한다. 실행 움직씨가 규칙을 호출하고 결과를 보여 준다. 키보드 게임이나 화면 애니메이션이 아니라 게임 규칙의 계산 실험이다.

예상 질문: 공격8·방어3이면 피해5, 체력12면 남은체력7이다. 방어가 공격 이상이면 피해0이다.

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 09A | [용사와슬라임](예제/09A_용사와슬라임.ddn) | 7 |
| 09B | [방어규칙경계](예제/09B_방어규칙경계.ddn) | 0 / 0 |
| 09C | [쓰러짐경계](예제/09C_쓰러짐경계.ddn) | 0 |
| 09D | [미로의열쇠](예제/09D_미로의열쇠.ddn) | 열림 / 잠김 |

수정 활동: 09A의 방어력을8로 바꾸면 남은체력12다. 09C의 체력을5로 바꾸어도 피해5면 남은체력0이다.

해설: 남은체력을 음수로 만들지 않는 규칙을 조건으로 구현했다. 09D의 열쇠는 실행 입력으로 쓰인 참거짓이며 실시간 행동 입력 API를 추가한 것이 아니다.

## 10차시 작은 상점의 진행을 움직씨로 만들기

상품금액 셈씨는 가격과 개수를 계산한다. 구매진행 움직씨는 구매 가능 여부와 잔액을 보여 준다. 실행 움직씨는 같은 규칙을 여러 상황에 적용한다.

예상 질문: 가격800·개수3이면2400이다. 잔액2000,2400,5000에서 상태와 잔액을 각각 예상한다.

| 활동 | 원문 | 예상 결과 |
|---|---|---|
| 10A | [작은상점](예제/10A_작은상점.ddn) | 구매 가능 / 2600 |
| 10B | [잔액부족](예제/10B_잔액부족.ddn) | 잔액 부족 / 2000 |
| 10C | [잔액딱맞음](예제/10C_잔액딱맞음.ddn) | 구매 가능 / 0 |
| 10D | [규칙을여러번](예제/10D_규칙을여러번.ddn) | 잔액 부족 / 2000 / 구매 가능 / 0 / 구매 가능 / 2600 |

수정 활동: 10A의 잔액을2000으로 바꾸어10B와, 2400으로 바꾸어10C와 대조한다. 10D의 세 잔액은 세 독립 실험이다.

해설: 이 예제는 구매 판정과 남을 잔액을 계산·출력한다. 지갑을 저장하거나 영속 상태를 갱신하는 상점이라고 부르지 않는다. 새 저장 기능·사건 훅을 몰래 추가하지 않는다.

## 보충 단일식 셈씨

`-->`는 함수 형 표시로, 받는 씨와 내는 씨의 관계를 나타낸다. 이름 있는 정의를 만드는 표지는 `:=`다(RD-376·RD-407). 예를 들어 `두배짧게 (값:수 --> 수) := 값 * 2.`에서 `-->`는 수를 받아 수를 내는 형을 표시하고, `:=`는 이름 두배짧게와 계산식을 정의로 결속한다. 이 선언 전체는 RD-406의 이름 있는 단일식 pure 셈씨이며, `-->` 자체가 셈씨를 정의하는 것은 아니다. 본문형과 받는자리·결과자리 관계를 먼저 이해한 뒤 뒤쪽 보충에서 짧게 쓰는 법을 배운다. 앞서 만든 [축약 대조 예제](보충/06_마지막에배우는축약.ddn)와 [값 수정 실습](보충/09_축약대조.ddn)을 보충으로 사용한다.

## 검증 범위

검증 도구 `tests/definition_centered_course_runner.mjs`는 본문40개·교정5개·수정10개·보충2개를 실제 CLI 세 이름과 WASM에서 실행한다. 기대값은 손 계산과 오류의 교육 의도에서 정하며, 정상52개는 출력과 세계 해시를 대조하고 의도한 오류5개는 양쪽에서 거부를 확인한다. 구체적 결과와 수정판 ZIP의 정체는 별도 검증 보고에 결속한다.

문법 실행기는 C5 기준이다. 수업 표현을 고치기 위해 새 문법이나 라이브러리를 만들지 않는다. `검증목록.json`은 교육 검증용 목록이지 새 실행·입력·재현 형식이 아니다. 학생 이해도, 독립검토, 공개 승인은 자동 검사로 대신하지 않는다.
