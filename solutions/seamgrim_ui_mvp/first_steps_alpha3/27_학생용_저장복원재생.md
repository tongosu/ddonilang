# 27차시 — 원문 저장, 상태 복원, 입력 재생은 다르다

## 설명

원문 저장은 내가 쓴 프로그램을 보존합니다. 실행 상태 저장은 원문과 함께 현재 세계·마디·실제로 처리한 입력 상태를 보존합니다. 입력 기록 재생은 시작 조건과 완전한 입력 기록을 다시 적용합니다. 화면이 비슷하다고 이 세 가지가 같은 기능이 되는 것은 아닙니다.

이번에는23A의 계산을 뿌리 파일과 `실행` 움직씨가 있는 작은 작품으로 작성합니다. 현재 실행 상태 저장은 명시 뿌리 작품에서 지원합니다. 단일 원문이 저절로 영구 작품이 되지는 않습니다. 저장 후 초기식10으로 돌아가면 이어서 계산한 것이 아닙니다.

## 예상

한 마디 후12, 두 마디 후14입니다. 여기서 저장했다고 합시다. 복원 후 한 마디는16이고, 처음부터 한 마디는12입니다. 두 상황을 표로 적고 왜 다른지 설명합니다.

## 실행

27A를 고르고 작품 자료에서 정체 만들기를 명시적으로 선택한 뒤 실행합니다. 일시정지하고 처음부터 시작해 한 마디 진행으로 합계12, 다음 마디14를 확인합니다. 작품 자료에서 현재 실행 상태 저장을 선택하고 파일을 내보냅니다. 재열기로 복원해 원문·마디·합계가 같음을 확인한 뒤 한 마디를 진행하면16입니다. 정체 만들기 없이 저장을 시도하면 거부되는 것이 정상입니다.

상태 파일은 원문 또는 입력 테이프 파일과 다릅니다. 엉뚱한 파일을 넣었을 때 조용히 빈 세계로 바뀌는 결과를 정상으로 받아들이지 마세요.

## 수정

새 실행의 시작값을20으로 고치고 저장 전 원문과 비교합니다. 원문이 다른데 기존 상태를 같은 실행이라고 주장할 수 있을까요? 기존20A/26A에서는 입력 기록 저장·재생을 따로 해 보고, 상태 복원과 어떤 정보가 다른지 설명합니다.

## 이유 설명

복원은 저장 시점에서 이어 가기이고 재생은 입력을 다시 적용하기입니다. 상태는 있지만 전체 입력 이력이 없으면 완전한 Tape 재생을 만들 수 없습니다. 현재 브라우저 저장 검사가 통과했다는 사실은 전원 손실 등 모든 복구 상황의 내구성 보장이 아닙니다. 글자 입력 같은 미지원 기능의 기록이 되는 것처럼 설명하지 않습니다.
