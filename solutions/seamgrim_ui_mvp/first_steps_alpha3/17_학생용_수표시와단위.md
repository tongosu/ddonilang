# 17차시 - 계산한 수와 읽기 좋은 표시

알파3 후보의 실습입니다. 첫걸음 메뉴에서17A·17B와 수정실습MOD17을 열고, 학생용17-20차시 PDF와 함께 읽습니다.

이번 시간에는 계산 결과를 고치는 것과 화면 표시를 읽기 좋게 만드는 것을 구별합니다. 그리고 길이를 시간으로 바꿔 넣는 실수를 단위로 잡습니다. 준비물은 셈그림, 세 원문, 결과를 적을 종이입니다. 40-50분 동안 **예상 → 실행 → 수정 → 이유 설명** 순서로 해 봅니다.

## 1. 예상하기 - 작은 차이는 어디서 생길까?

높이 20에서 속도 9.8에 간격 0.1을 곱한 값을 빼면 손 계산은 19.02입니다. `17A_계산과표시.ddn`을 읽고 세 출력 줄을 예상하세요. 셈씨 `다음높이`는 세 받는자리의 역할을 이름 인자로 밝히고 수 하나를 돌려줍니다.

```ddn
결과 <- (높이=20,속도=9.8,간격=0.1) 다음높이.
결과 보여주기.
(-결과) 보여주기.
"19.019999999" 보여주기.
```

| 줄 | 내 예상 | 실행 결과 |
|---|---|---|
| 계산한 수 | | |
| 부호를 바꾼 수 | | |
| 따옴표 안의 글 | | |

한 마디 실행합니다. 계산한 수의 표시는 `19.02`, 음수는 `-19.02`입니다. 글은 `19.019999999` 그대로입니다. 숫자처럼 생겼어도 글을 수로 추측해서 고치지 않습니다.

## 2. 표시와 계산은 다르다

실행기는 고정 정밀도의 수로 계산합니다. 어떤 십진 소수는 내부 표현과 아주 작은 차이가 납니다. 화면은 현재 표시 정책에 따라 소수점 아래 여섯 자리까지 반올림하고 끝의 0을 생략합니다. 이때 계산 값·입력 기록·세계 해시는 고치지 않습니다. 화면이 예쁘다고 계산이 더 정확해진 것은 아닙니다.

`1 / 128`은 `0.0078125`입니다. 현재 여섯 자리 표시에서는 정확히 중간일 때 마지막 자리를 짝수로 만드는 반올림을 써서 `0.007812`로 보입니다. 반면 `3 / 128`은 `0.023438`로 보입니다. 무조건 끝을 버리는 규칙과 비교해 보세요.

## 3. 길이와 면적 - 무엇이 같은가?

`17B_차원을유지하기.ddn`을 엽니다. `@m`은 미터, `@cm`은 센티미터입니다. 같은 길이를 나타내는 다른 단위이므로 거리 이름에 다시 넣을 수 있습니다. 표시 결과는 `1@m`입니다. `2@m * 3@m`은 길이 둘을 곱한 면적이며 `6@m^2`입니다. 그 면적에 다른 면적을 넣으면 `20@m^2`로 바뀝니다.

```ddn
거리 <- 1@m.
거리 <- 100@cm.
면적 <- 2@m * 3@m.
면적 <- 4@m * 5@m.
```

단위 환산도 현재 수 계산을 따릅니다. 표시가 같은 것과 내부 수의 모든 비트가 같은 것은 별개입니다. 대신 **같은 원문·같은 입력의 CLI와 WASM 결과가 같은가**로 재현을 확인합니다.

## 4. 수정하기

`MOD17_음수와단위.ddn`을 실행하기 전에 `0 - 0.8 × 0.1`을 계산합니다. 두 출력은 `-0.08`, `2@m`입니다.

1. 속도를 1로 바꿉니다. 첫 출력은 어떻게 될까요?
2. `200@cm`를 `2@s`로 바꾸고 실행합니다. 길이 이름에 시간을 넣는 것은 왜 거부돼야 할까요? 오류를 읽은 뒤 되돌려 정상 실행합니다.
3. `면적`의 마지막 값을 `1@m`로 바꿉니다. 숫자 1 자체가 아니라 무엇이 맞지 않는지 설명합니다.
4. 원문을 저장한 뒤 다시 열어 같은 실험을 합니다. 표시와 단위가 유지되는지 봅니다.

## 5. 오늘의 확인

- `보여주기`가 받은 수와 따옴표 안의 글을 구별할 수 있다.
- 표시 반올림이 세계 계산을 바꾸지 않는 이유를 말할 수 있다.
- 길이의 단위 환산과 차원이 바뀌는 재결속을 구별할 수 있다.
- 오류 하나를 읽고 원문을 고쳐 다시 실행했다.
