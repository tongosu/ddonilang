# 20차시 - 사건의 순서를 읽는 반응

이번에는 행동 사건을 알림씨로 받아 움직씨가 처리하는 원문을 읽습니다. 20A는 계산값2에서 시작합니다. 왼쪽 키는 **더함**, 오른쪽 키는 **곱함** 행동으로 바뀝니다. 세계는 키 이름이 아니라 논리 행동을 받습니다. 알파3의 입력-알림 연결 이름은 잠정 설계입니다.

## 1. 먼저 예상하기

같은 마디에서 더함 다음 곱함이면 `(2+1)×2=6`, 곱함 다음 더함이면 `2×2+1=5`입니다. 행동의 종류만 세는 것으로는 순서를 설명할 수 없습니다. 키를 누른 채 두는 상태와 누름 사건 한 번도 다릅니다.

## 2. 원문 읽기

```ddn
채비 { 계산값:수 := 2. }.
(채널:글, 알림:글, 순서:수, 마디번호:수) 조작알림:알림씨 := { 없음. }.
계산받는이:임자 := {
  (받은:조작알림) 계산반응:움직씨 {조작알림을 받으면} := {
    { 받은.채널 == "더함" }이면 { 계산값 <- 계산값 + 1. }
    아니면 { 계산값 <- 계산값 * 2. }.
  }.
}.
```

알림씨는 사건의 값을 담고, 임자는 반응할 움직씨를 가집니다. `받은.채널`을 읽어 어떤 계산을 할지 정합니다. 채비는 새 세계를 시작할 때 초기 상태를 준비합니다. 매마디마다2로 되돌리지 않습니다.

## 3. 실행하고 기록하기

20A를 고르고 안내의 **이 활동의 논리 입력 계약 선택**을 누릅니다. ▶로 실행한 뒤 왼쪽·오른쪽 키를 순서대로 누릅니다. 결과표의 반응결과와 매마디결과를 읽습니다. 키를 뗄 때 생기는 사건도 기록되므로, 직접 누르기 실험에서 언제나6이나5가 나온다고 단정하지 마세요. 고정된 한 마디 순서 비교는 교사용 재생 검사로 확인합니다.

일시정지 후 기록을 봉인·저장하고 같은 원문과 계약으로 다시 재생합니다. 새로 시작해 반대 순서를 시험합니다. 초기 상태를 되돌리지 않은 두 실행의 최종값만 비교하면 순서 실험이 아닙니다.

## 4. 바꾸고 설명하기

더함의1을3으로 바꾼다면 두 순서의 예상값은10과7입니다. 원문을 바꾸면 입력 계약의 원문 해시도 바뀌므로 기존 계약을 몰래 재사용해서는 안 됩니다. 우선 종이에 계산하고 원문을 읽어 설명하세요. 새 실험 계약은 명시적으로 다시 만들어야 합니다.

반응은 사건마다 앞 사건의 반영 상태를 보고, 매마디는 그 뒤 결과를 봅니다. 반응이 사건을 소비하여 조회에서 사라지게 하지 않습니다. 마디가 실패하면 그 마디 일부 결과를 정상 결과처럼 게시하지 않습니다.
