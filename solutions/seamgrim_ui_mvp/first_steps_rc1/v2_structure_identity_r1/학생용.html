항등 짜임교사용

입력을 그대로 돌려준다는 것은?

지정된CLI 고정 실행물과 함께 사용합니다. 다른 판의 실행물이나 아직 연결하지 않은 셈그림에서 같은 지원을 가정하지 않습니다.

1. 정의와 근거를 읽기

어떤 셈씨에7을 넣었더니7이 나왔습니다. 이 한 번의 결과만으로 모든 입력을 그대로 돌려준다고 말할 수 있을까요? 항상7을 돌려주는 셈씨도 이 실험에서는7을 출력합니다.

제공된 정상 원문의 첫 정의를 읽어 보세요. 본문은 숫자7이 아니라 받는자리의 값을 반환합니다.

(값씨:씨자리) 두고
(값:값씨~을)
그대로:값씨:셈씨 := { 그대로 <- 값. }.

값씨는 이 정의에서 사용하는 씨의 자리입니다. 다음 정의는 제공 원문의 바른수에 연결된 계산을 사용합니다.

(값:바른수~을)
바른수그대로:바른수:셈씨 := {
  바른수그대로 <- (값=값) 그대로.
}.

항등구조 := (바탕씨=바른수, 연산=바른수그대로) 항등법칙요구짜임.

짜임에서 어떤 씨와 어떤 연산을 묶었는지 찾아보세요. 이름에 ‘그대로’가 들어갔다는 사실만으로 올바른 항등 연산이 되는 것은 아닙니다.

정상 원문 전체의 법칙전달과 법칙필수계산은 지정한 구조에 속한 근거를 받습니다. 서로 다른 구조의 근거를 형태가 비슷하다는 이유로 대신 쓸 수 없습니다. 첫 수업에서는 제공된 앞부분을 유지하고 마지막 호출부터 읽습니다.

((값=7, 근거=항등구조.법칙) 법칙필수계산) 보여주기.

고정 CLI·Node WASM에서 같은 원문의 출력7을 확인했습니다. 교사가 지정한 고정 실행물 ddonilang.exe를 쓰는 터미널에서 이 교재 폴더로 이동해 실행합니다. 다른 이름의 실행물을 임의로 대신 고르지 않습니다.

ddonilang.exe run 원문/01_실제7.ddn --source-profile v1-core-v25 --madi 1 --json

이 명령은 고정 검사와 같은 구조화 결과를 냅니다. 계산 출력은 output_display.texts의7입니다. 상태 해시나 경고를 프로그램 출력과 섞지 마세요. 기존 호출 꼬리 경고가 남아 있을 수 있으므로 실제 오류 등급과 실행 결과를 구분합니다.

2. 상수7과 항등을 구별하기

이번에는 다른 입력 원문의 두 호출을 읽고 결과를 예상하세요. 고정 CLI·Node WASM에서 순서대로23과-2를 확인했습니다.

((값=23, 근거=항등구조.법칙) 법칙필수계산) 보여주기.
((값=-2, 근거=항등구조.법칙) 법칙필수계산) 보여주기.
입력입력을 그대로 반환항상7을 반환
777
23237
-2-27
ddonilang.exe run 원문/02_실제다른값.ddn --source-profile v1-core-v25 --madi 1 --json

7이라는 입력만으로는 두 정의를 구별할 수 없지만23에서는 구별할 수 있습니다. 그렇다고 몇 가지 값을 시험한 사실만으로 모든 입력에 대한 수학 증명이 완성되는 것은 아닙니다.

상수7 거부 원문에서는 처음 정의의 반환이 다음처럼 바뀌어 있습니다.

그대로:값씨:셈씨 := { 그대로 <- 7. }.

검사 대상은 ‘원하는 출력이 한 번 나왔는가’뿐 아니라 이 지원 범위의 실제 정의와 구조·연산 결속입니다. 상수7을 정상 항등의 근거로 등록해서는 안 됩니다.

잘못된 근거와 고치기

  • 법칙 누락: 필수 근거를 빼고 계산을 호출합니다. 어떤 받는자리가 빠졌는지 정상 원문과 대조하세요.
  • 참으로 대신하기: 일반 값 참을 구조의 법칙 근거 자리에 넣습니다. 성공이라는 말이나 참 값을 적는 것으로 필요한 근거가 생기지 않습니다.
  • 다른 구조: 호출과 근거가 같은 구조를 가리키는지 읽습니다. 정상 원문의 구조 결속으로 복원합니다.

‘고치기’는 임의 근거를 만드는 활동이 아닙니다. 상수7은 그대로 <- 값.으로,누락된 근거는 제공 정상 원문의 받는자리·호출로,다른 구조의 근거는 같은 항등구조의 연결로 복원합니다. 수정 뒤 같은 고정 실행물에서 다시 확인합니다.

상수7은 E_PROOF_STRUCTURE_POLICY,필수근거 누락은 E_CALL_REQUIRED_PIN_MISSING,위조·다른 구조는 E_PROOF_STRUCTURE_CONSUMPTION으로 거부된 사례입니다. Node WASM은 일부 정적 거부를 바깥 E_PARSE와 내부 원인으로 포장합니다. 포장 차이를 수용/거부 차이로 읽지 않습니다.
