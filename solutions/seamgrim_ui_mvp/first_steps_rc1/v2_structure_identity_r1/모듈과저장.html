항등 짜임교사용

시작 정의를 선택하고 원문을 다시 읽기

앞 수업은 단일 원문 끝에서 계산을 호출했습니다. 이번에는 실제 모듈의 움직씨 본문에서 항등 계산을 부릅니다. 기존 두 수업의 정의·근거는 그대로 읽고, 어디에서 실행을 시작하는지 비교하세요.

root와 app의 역할

작품의 root.ddn에는 시작 모듈과 정의가 적혀 있습니다. 실제 구현은 app.ddn에 있습니다. 첫 작품은 실행을 선택합니다.

시작=(모듈=앱, 정의=실행)

실행:움직씨 := {
  ((값=7, 근거=항등구조.법칙) 법칙필수계산) 보여주기.
}.

위는 역할을 설명하는 발췌입니다. 전체 정의·root를 갖춘 실제 가상 작품 파일을 사용합니다. 설명의 일부만 따로 복사해 완성 원문이라고 실행하지 않습니다.

ddonilang.exe project-run --virtual 모듈/01_모듈7.project.json

지정된 후속 고정 실행물에서 출력7이 확인된 명령입니다. CLI의 구조화 결과와 Node WASM 결과의 계산 출력·state_hash가 같은 근거가 있습니다. 아직 이 수업에 Chrome 실행 버튼이 붙었다는 뜻은 아닙니다.

다른 시작 정의 고르기

선택 시작23 작품에는 실행과 다른실행이 함께 있습니다. root는 다른실행을 선택합니다. 이름이 실행인 정의를 무조건 먼저 부르는 것이 아닙니다.

시작=(모듈=앱, 정의=다른실행)

다른실행:움직씨 := {
  ((값=23, 근거=항등구조.법칙) 법칙필수계산) 보여주기.
}.
ddonilang.exe project-run --virtual 모듈/02_선택시작23.project.json

이 작품의 기대·관측 출력은23 하나입니다. 기존 단일 원문 두 번째 예제의23과-2 두 출력과 구별합니다. 실행을 더 쉽게 보이게 하려고 최상위로 호출을 옮기지 않습니다.

원문 저장·다시 읽기는 무엇을 확인할까?

후속 고정 제품의 Native API 검사에서는 다음 순서를 확인했습니다. 이는 버튼을 누른 Chrome 수업이 아니라 별도 프로세스에서 API를 호출한 실제 검사입니다.

  1. 공개 create API가 만든 정본 작품 자료를 사용합니다.
  2. 원문 저장의 성공과 프로세스 정상 종료를 확인합니다.
  3. 새 프로세스에서 같은 원문을 load하고 정상 종료합니다.
  4. 명시적으로1마디를 새로 실행해 출력7과 원문 보존을 확인합니다.

검사 환경은 작성자의 C:전용 로컬 임시 저장소입니다. 저장했던 실행 세계를 이어간 검사가 아니며,세계 이어 실행·정전 복구·모든 드라이브의 성공을 뜻하지 않습니다. I:에서는 첫 실행120초 timeout 기록이 남아 있습니다. C:의 성공으로 이 실패 원인을 확정하거나 복구됐다고 하지 않습니다.

도구가 만든 작품 자료는 그대로 보관하기

공급된 canonical 작품 자료는 도구용 자료의 보관 사본입니다. 일반 가상 작품 파일과 임의로 맞바꾸지 않습니다. Native 요청의 authored_project_json_utf8에는 create가 반환한 문자열을 그대로 전달합니다.

그 문자열을 JSON으로 읽은 뒤 예쁘게 다시 출력하거나 열쇠 순서·공백·줄끝·escape를 손으로 바꾸지 않습니다. 눈에 같은 원문이 보여도 도구가 확인할 자료의 바이트가 달라질 수 있습니다. 변경은 공개 원문 갱신 API를 통해 새 정체로 처리하며,학생이 hash나정본 JSON을 손으로 고쳐 저장을 통과시키지 않습니다.

새 실험은 교사가 준비한 새 작품·자기 저장소로 진행합니다. 기존 검사 저장소를 재사용·삭제하거나 OS보호 자료·권한 파일을 옮기지 않습니다. 이 교재에는 그 저장소와 실행파일을 포함하지 않습니다.

거부와 설명

가짜 항등·가짜 근거·지역 가림·모듈 최상위 실행·실제 곱셈 넘침·값 타입 오류는 정상 결과로 바꾸지 않고 거부된 사례입니다. 원문이 바뀌었는데 이전 저장 근거로 load하려는 경우도 거부됩니다. 정상 모듈 원문과 맞는 정본 자료로 되돌리되,낡은 성공 기록을 현재 결과로 붙이지 않습니다.
