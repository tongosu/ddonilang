# 같은 등식을 한 단계씩 바꾸기

## 먼저 예상하기

`1+(3/2)t=7`이 주어졌다고 생각해 봅시다. 양변에서1을 빼면 `(3/2)t=6`입니다. 이어 양변을3/2로 나누면 `t=4`입니다. 여기서는 단위 없는 정확한 유리수의 등식을 다룹니다. V3의 시간 단위를 화면에서 몰래 없애 가져온 문제가 아닙니다.

## 원문을 보고 작성하기

이 수업은 고정 생산자9792 개발판의 실제 web 검사로 확인했습니다. ‘등록 작품 자료’를 세부→작성 정체 자료→파일 가져오기로 열고 풀이.ddn을 선택합니다. 파일의 ‘미지수’가 설명의 t에 해당하는 실제 받는자리입니다. 원문을 실행해 출력하는 수업이 아니라, 가정에 의존한 각 등식 변형을 검사하는 수업입니다. 정식 배포·Native 저장 완료 예제라는 뜻은 아닙니다.

탐구 노트에서 ‘풀이 작성’을 펼칩니다. ‘현재 원문 읽기’로 실제 편집 중인 파일을 읽습니다. ‘전체 DDN 원문’에서 바꿀 부분을 선택하고 조작·근거·항 또는 계수·왼쪽 식·오른쪽 식·두 단계 이름을 적습니다. ‘선택 범위에 두 줄 넣기’는 조작과 등식정리 두 줄을 함께 보여 줍니다. 수학을 검사하거나 정답을 채우는 버튼은 아닙니다.

전체 원문을 확인하고 ‘편집기에 적용’을 누릅니다. 다른 파일이나 작품으로 바뀌었다면 적용하지 않습니다. 작성 중인 내용은 남으므로 필요한 부분을 별도로 보관한 뒤 현재 원문을 다시 읽습니다. 마지막 정리가 함수의 명명 결과자리로 가는 경우 ‘명명 결과자리’를 선택하고 실제 결과 이름 ‘일차결론보이다’를 적습니다. 이때 두 번째 줄은 정의 `:=`가 아니라 결과자리 대입 `<-`입니다.

‘검사’를 명시적으로 누릅니다. 정상 원문은 양변빼기·등식정리·양변나누기·등식정리의 네 원문 단계가 검사됩니다. ‘실제 단계 원문’을 펼쳐 어느 코드가 검사됐는지 확인합니다. 이번 가정 아래의 수용이지 무가정 정리 발급이 아닙니다. 편집하면 이전 결과가 지워지고 다시 검사하기 전 NOT_PRODUCED입니다.

## 틀린 중간 단계를 찾기

두 번째 등식을 `(3/2)t=5`로 적었지만 양변에서 뺀 항은1이라고 했다고 생각해 봅시다. 마지막 답을4로 적어도 그 중간 단계가 옳아지지는 않습니다. 공통 checker가 처음 잘못된 단계를 알려 주면 그 근거와 양쪽 식을 읽고5를6으로 고친 뒤 직접 다시 검사합니다. 아직 검사하지 않은 후속 단계를 성공으로 읽지 않습니다.

중간 오류의 실제 진단은 `E_PROOF_ALGEBRA_REWRITE`이며 오른쪽 항이 앞선 증거와 맞지 않다고 설명하고 원문의5를 가리킵니다. 후속 두 단계는 미검사입니다.

나눌 계수를0으로 적는 것은 허용되는 등식 변형이 아닙니다. 실제 진단은 `E_PROOF_ALGEBRA_DIVIDE_ZERO`: ‘양변을0으로 나눌 수 없습니다’입니다. 방정식의 해가 없다는 뜻도 아닙니다. 계수를3/2로 고친 뒤 다시 명시 검사합니다. 두 거부와 수정 후 수용을 같은 실제 web 검사 경로에서 확인했습니다.

## 저장 후 다시 열기

보존할 것은 문제·가정·풀이·근거의 실제 원문입니다. 성공 JSON이나 proof handle을 저장하는 기능이 아닙니다. 재열기 뒤 결과는 NOT_PRODUCED이며, 자동 검사하지 않고 사용자가 다시 명시 검사합니다. 이 V4 작품의 실제 Native admission·정상 종료·새 프로세스 재열기는 최종 결합 실행물로 확인할 예정이며 아직 미실행입니다. web 검사 수용만으로 저장됐다고 생각하지 않습니다.
