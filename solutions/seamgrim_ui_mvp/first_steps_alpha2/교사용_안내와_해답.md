# 첫걸음 11-16차시 - 교사용 안내와 해답

수업 목표는 정의를 읽고 독립적으로 예상한 결과를 실제 실행과 대조하는 것입니다. 1-10차시의 정의·이름 핀·조건·차림 지식을 사용합니다. 학생은 원문을 먼저 읽고 계산을 예상해야 하며, 실행 출력을 그대로 답으로 옮기는 활동으로 끝내지 않습니다.

## 준비와 평가

6차시, 본문 예제12개, 실제 수정 예제6개를 사용합니다. `README.md`가 학생용 자료이며 두 PDF는 같은 Markdown에서 생성합니다. `검증목록.json`은 교육 자산 목록입니다. 기존 제품의 논리 입력 계약·요청 JSON을 교육용 목록과 구분하십시오. SSOT나 새 영구 입력 형식으로 취급하지 않습니다.

한 차시 45분 권장: 원문 읽기·예상 10분, 실행·관찰 10분, 수정 15분, 설명·비교 10분. 두 예제의 결과를 읽는 것보다 **다른 역할을 가진 두 정의를 설명하는 것**을 평가합니다. 학생이 작은 값 하나를 직접 바꾸고 예상과 관찰의 차이를 설명해야 완료입니다.

준비: 최신 셈그림, 실제 Native3, 실제 WASM, 이 코스 폴더. 정적 예제는 한 마디, 매마디 예제는 목록의 ticks 수만큼 실행합니다. 상단 ▶·Ⅱ·한마디·중지를 사용합니다. 새 실행과 이어서 진행을 구분하세요. 15-16의 실제 키 입력은 으뜸 보개에 초점을 둡니다. 수업 원문에 대한 UI 통합·동작 검사는 별도 제품 검증입니다.

대표 CLI 실행은 압축본 루트에서 다음과 같습니다.

```text
bin/ddonilang.exe 실행 solutions/seamgrim_ui_mvp/first_steps_alpha2/예제/11B_두칸씩전진.ddn --source-profile v1-core-v25 --마디수 4 --json
```

여기서 JSON은 실행기가 출력한 결과입니다. 학생용 기대값 목록을 실행 입력으로 넣는 방식이 아닙니다. 실제 보개·마디값·입력 기록은 아래 원문 검사와 브라우저 검사에서 각각 확인합니다.

## 11차시 - 모양과 매마디 해설

11A는 중심 `(2,1)`, 반지름 `0.5`, 출력 `2,1,0.5`입니다. 모양만 정의했으므로 시간이 지난다는 이유로 움직이지 않습니다. 이름 핀 `가로`, `세로`, `크기`를 각각 다른 역할로 읽게 합니다. 학생에게 좌표 두 값의 순서를 바꾸면 무엇이 달라지는지 묻습니다.

11B는 시작 위치 0에서 매마디 2씩 더합니다. 네 마디 위치는 `2,4,6,8`, 차례는 4입니다. MOD11은 증가량을 3으로, 가로 범위를 `[-1,14]`로 바꾸므로 `3,6,9,12`입니다. 틱별 누적 출력과 마지막 원 중심이 모두 일치해야 합니다.

```ddn
(시작)할때 { 위치 <- 0. 차례 <- 0. }.
(매마디)마다 { 차례 <- 차례 + 1. 위치 <- 위치 + 2. 위치 보여주기. }.
```

흔한 오류: `위치 <- 0`을 매마디에 넣으면 매번 초기화되어 2만 나옵니다. 작품의 최상위 값 배정도 마디마다 다시 평가될 수 있으므로 진행 상태의 초기화는 시작 훅에 둡니다. `위치그림`은 위치를 받아 그림을 계산하며, 위치를 전진시키는 규칙은 매마디 훅입니다. 프레임 속도와 한 마디 이동량을 혼동하지 않게 합니다.

평가 질문: 11A를 네 마디 돌려도 왜 출력 패턴이 반복될 뿐 위치는 그대로인가요? 11B를 한마디 네 번 진행한 것과 같은 입력으로 네 마디 실행한 것은 어떤 조건에서 같나요?

## 12차시 - 보기값 셈씨와 장면 해설

12A는 `0.5×3=1.5`를 수 셈씨 `배율반지름`에서 계산합니다. 보기값 셈씨 `크기그림`은 반지름 1.5인 원, 가로·세로 범위 `[-4,4]`를 장면으로 묶고 `표준보기.장면`으로 돌려줍니다. MOD12는 배율4이므로 반지름2입니다. 두 경우 중심 `(0,0)`은 같습니다. 반지름3배가 원 넓이3배라는 답은 틀립니다. 이 수업은 넓이 공식을 구현한 원문이 아닙니다.

12B의 넓이는 `6×4÷2=12`, 꼭짓점은 `(0,0),(6,0),(0,4)`입니다. 결과값과 실제 장면 꼭짓점을 함께 확인합니다. 장면은 요소 목록과 좌표 범위를 포함합니다. 그 장면으로 만든 보기값은 하나의 수와 다른 결과 종류입니다.

흔한 오류: 식을 계산한 셈씨에서 결과 이름 배정을 빠뜨리는 경우, 보기값 셈씨에 수를 돌려주는 경우, 계산과 그림에 서로 다른 밑변을 전달하는 경우. 역할이 다른 인자는 `(밑변=6,높이=4)`처럼 이름 핀을 써서 확인합니다. 억지 조사나 정의 결과 이름에 ‘하기’를 붙이지 않습니다.

평가: 원의 반지름을 바꿔 그림도 바뀌게 한 뒤 왜 중심은 그대로인지 말하게 합니다. 삼각형 원문에서 넓이 셈씨와 그림 셈씨를 각각 찾아 입력·결과 종류를 설명하게 합니다.

## 13차시 - 보개짜임 해설

13A의 관계는 `primary,overlay`, 공 중심은 `(-2,0),(2,0)`, 두 중심 사이 거리는4입니다. MOD13은 비교 중심 `(1,0)`, 거리3입니다. 겹의 `기준=기준보기`와 `순서=1`을 읽게 합니다. 같은 좌표 범위를 써야 비교 그림의 위치를 같은 축에서 해석할 수 있습니다.

13B의 관계는 `primary,side`. 으뜸 공은 `(2,5)`, 오른쪽 곁은 결과표이며 출력은 `2,5`입니다. 원문의 `(x:가로,y:세로) 내보임`은 결과표 자료, 두 `보여주기`는 출력 기록입니다. 표가 있다는 사실을 게임 세계가 추가로 계산됐다는 뜻으로 설명하지 않습니다.

흔한 오류: 관계를 만들고 짜임의 차림에서 빠뜨리는 경우, 다른 으뜸을 기준으로 지정하는 경우, 곁 보기를 두 번째 세계로 이해하는 경우. 짜임은 한 작품에서 보기의 관계를 결속합니다. 결과표를 닫거나 재배치하는 화면 조작은 원문 계산과 구분합니다.

평가: 출력숫자만 맞는 답을 충분한 것으로 처리하지 않습니다. 으뜸과 겹의 좌표, 곁의 종류와 자리, 짜임에 포함된 관계를 학생이 직접 설명해야 합니다.

## 14차시 - 물체 돋 해설

14A는 공 중심 `(1,2)`, 반지름0.5, 출력 `1,2`입니다. `공대상`과 으뜸에 그린 공이 같은 형상을 가리키며, 돋의 보기법은 `공자세히`라는 명명된 셈씨입니다. 그 셈씨가 받은 `대상`을 다시 장면에 넣는 점을 확인합니다. MOD14에서는 둘 모두 `(-1,2)`로 옮기고 안내 글·출력도 고칩니다.

14B의 세 마디 출력은 `1,2,3`. 마지막 으뜸 공과 돋 대상의 중심은 `(3,0)`입니다. `이동대상`이라는 작성 정체는 유지되고 현재 위치가 바뀝니다. 현재 제품의 물체 정체는 실행 중 임시 정체입니다. 다른 원문·다른 실행·영구 저장까지 같은 정체를 보장한다고 가르치지 않습니다.

평가에서는 돋의 대상, 받은 셈씨 인자, 현재 위치가 같은 물체에 결속되는지 확인합니다. 브라우저에서는 실행 중 공을 눌러 선택 표시와 자세한 보기를 관찰하고, Ⅱ로 멈춰 값을 읽게 합니다. 원문 검사는 실제 투영 자료의 같은 중심과 선택 대상 일치를 확인하며, 교실의 클릭 동작 자체는 브라우저에서 확인해야 합니다.

흔한 오류: 표시 그림만 바꾸고 돋 대상을 옛 위치에 남기는 경우. 기존 공을 전역으로 읽는 대신 필요한 값을 이름 핀으로 받거나 셈씨 안에서 동일한 형상을 계산합니다. 학생용 구조 설명의 `...`는 완전한 실행 원문이 아니므로 복사 실행하지 않게 합니다.

## 15차시 - 논리 입력 작은 게임 해설

15A의 고정 요청 여섯 마디 결과는 위치·점수 순서로 `(1,0),(2,0),(3,0),(3,10),(2,10),(2,10)`입니다. MOD15에서는 보상20으로 바뀌어 마지막 점수20입니다. 위치3의 득점, 위치2에서 득점하지 않는 분기, 0~3 범위를 설명하게 합니다. 방향키 이벤트를 직접 읽는 대신 `입력사상.사건들`의 채널·종류를 읽습니다.

15B는 0에서 첫 마디 오른쪽→회전: `(0+2)×3=6`. 둘째 마디 회전→오른쪽: `6×3+2=20`. 셋째 다시시작0, 넷째 입력 없음0입니다. 최종0만 비교하면 앞 마디의 순서 오류를 놓치므로 모든 마디를 확인합니다.

행동 연결표는 기존 `ddn.input_action_map.v1`, 계약은 기존 `v1-core-v25-logical-alpha2`와 기존 알파2 Control 채널입니다. 교육 작품은 연결된 행동의 일부만 소비합니다. 호출 한 번이 사건을 없애는 구조가 아닙니다. 학생의 자유 키 입력과 동봉 요청 파일의 정확한 마디·순서를 구분합니다. 수동 키 입력을 정해진 마디와 같다고 추정하지 않습니다.

```text
bin/ddonilang.exe 논리입력기록 solutions/seamgrim_ui_mvp/first_steps_alpha2/예제/15A_세칸이동게임.ddn solutions/seamgrim_ui_mvp/first_steps_alpha2/입력/15A.request.json 새15A.tape
bin/ddonilang.exe 논리입력재생 solutions/seamgrim_ui_mvp/first_steps_alpha2/예제/15A_세칸이동게임.ddn 새15A.tape solutions/seamgrim_ui_mvp/first_steps_alpha2/입력/15A.binding.json
```

새 파일명을 사용해 학생 기록을 덮어쓰지 않습니다. 위 기록은 실제 기존 제품 인코딩이며 교재 전용 변환기를 거치지 않습니다.

## 16차시 - 기록과 재생 해설

같은 세 사건 누름→반복→뗌에서 16A 이동수는 `1,2,2`, 16B는 `1,1,1`입니다. MOD16은 누름당2를 더하므로 `2,2,2`. 뗌은 눌림 상태를 끝내지만 이 작품의 이동 규칙에서는 이동수를 늘리지 않습니다. 누름과 반복을 구분하는 조건문이 결과 차이를 만듭니다.

같은 사건 목록을 다른 원문으로 새로 실행하는 실험은 가능합니다. 그러나 원문 hash를 포함한 기존 봉인 기록을 변경 원문에 붙이는 것은 거부됩니다. 수정본은 수정본 계약과 요청을 함께 사용합니다. `source_revision`을 고쳐 옛 파일의 무결성 검사를 우회하지 않습니다.

학생에게 기록 저장·재생 전 원문 사본, 입력 계약, 입력이 멈춘 상태를 확인하게 합니다. ▶ 실행·Ⅱ 정지와 대기 사건 반영을 구분합니다. 초점 상실이나 큐 손실은 새 세션으로 회복하며 가짜 뗌·기본 입력을 만들어 ‘같은 기록’이라고 하지 않습니다.

평가: 원문과 입력 목록을 보존하여 재실행하고, 각 마디 결과가 같은지 확인합니다. 16A와16B가 같은 결과여야 한다고 답하면 조건문 차이를 다시 읽게 합니다. 마지막 화면이 같다는 것만으로 입력 기록 전체가 같다고 판정하지 않습니다.

### 실행 검증 명령과 범위

```powershell
$env:DDN_NATIVE_DIR='./bin'
node tests/alpha2_course_runner.mjs
```

이 검사는 원문18개를 직접 실제 Native3와 WASM에 전달합니다. 출력, 마디별 독립 기대값, 수 자원, 장면 중심·반지름·꼭짓점·짜임·돋 대상, 세계 hash를 비교합니다. 논리 예제6개는 증분 실행·일괄 기록의 동일성, Native3가 기록한 기존 tape 바이트와 WASM 바이트의 동일성, 양방향 실제 재생을 검사합니다. 새 wire·새 언어 함수·테스트용 원문 lowering은 없습니다.

브라우저 교육패널 연결·실제 키보드 흐름·최종 배송 ZIP·Owner 체험·외부 공개는 별도의 대상 검증입니다. 교육 원문 검사 PASS를 그 Gate로 확대하지 않습니다.

공개 ZIP에서는 압축을 푼 최상위 폴더에서 위 명령을 실행합니다. `./bin`은 동봉 실행 파일 폴더입니다.
