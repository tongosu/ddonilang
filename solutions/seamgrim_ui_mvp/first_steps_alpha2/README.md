# 또니랑 첫걸음 11-16차시

정의로 계산하고, 그 계산을 그림과 입력이 있는 작품으로 넓힙니다. 1-10차시에서 배운 이름 핀, 셈씨, 움직씨, 조건, 차림을 그대로 씁니다. 각 차시는 40-50분이며 **예상하기 → 실행하기 → 수정하기 → 해설 확인** 순서로 진행합니다.

## 수업을 시작하기 전에

각 차시에는 원문 두 개와 수정 실습 한 개가 있습니다. `예제/`와 `수정실습/`의 `.ddn` 파일이 실제 실행 원문입니다. PDF는 읽는 자료이고, 원문을 편집하려면 `.ddn` 파일을 여세요. 예제를 실행하기 전에 자기 작업을 저장하고 원문 사본을 만듭니다.

상단 ▶는 실행, Ⅱ는 일시정지, 한마디는 다음 마디 진행, 중지는 진행을 끝내는 조작입니다. 정적인 예제는 한 마디만 실행합니다. 매마디 예제는 표에 적힌 마디 수만큼 진행하세요. 처음부터 비교할 때에는 새 실행을 시작합니다. 한마디를 누른 횟수와 출력된 마디를 함께 적습니다.

15-16차시는 논리 입력 계약과 행동 연결표를 함께 엽니다. 키를 받는 곳은 **으뜸 보개**입니다. 편집 칸에 초점이 있으면 키는 글을 고치는 데 쓰입니다. 으뜸 보개를 누른 뒤 조작하세요. `입력/action_map.json`의 연결은 ←=왼쪽, →=오른쪽, ↓=아래, ↑=회전, Space=떨어뜨리기, r=다시시작입니다. 작품이 쓰지 않는 행동도 연결표에는 남아 있으며 세계 값을 바꾸지 않습니다.

`검증목록.json`은 수업의 예제·기대값 목록입니다. 언어 문법이나 새 실행 입력 형식이 아닙니다. `입력/*.binding.json`과 `*.request.json`은 기존 알파2 논리 입력 제품 형식입니다. 알파1 기록과 논리 입력 기록을 섞지 마세요. 원문을 바꾸면 이전 기록을 그 원문에 붙이지 않고 새 실행·새 기록을 만듭니다.

### 여섯 차시의 목표

| 차시 | 만드는 것 | 새로 확인할 것 |
|---|---|---|
| 11 | 정지한 원과 움직이는 원 | 모양과 매마디 변화의 차이 |
| 12 | 계산한 크기와 삼각형 | 수를 돌려주는 셈씨와 보기값 셈씨 |
| 13 | 겹친 그림과 결과표 | 으뜸·겹·곁을 짜임으로 결속 |
| 14 | 선택한 공의 자세한 보기 | 같은 물체의 정체와 현재 위치 |
| 15 | 위치·점수 규칙 게임 | 물리 키와 논리 행동, 사건 순서 |
| 16 | 기록한 조작의 재실행 | 누름·반복·뗌, 원문과 기록의 결속 |

## 11차시 - 모양과 매마디

목표: 같은 원이 **어디에 있는지**와 **언제 움직이는지**를 따로 설명합니다.

먼저 [11A 원의 자리](예제/11A_원의자리.ddn)를 읽습니다. `(가로=2,세로=1,크기=0.5)`처럼 역할 이름을 붙이면 숫자 세 개의 뜻이 분명해집니다. `차림[가로,세로]`가 중심이고 반지름은 크기입니다. 가로가 커지면 오른쪽, 세로가 커지면 위쪽입니다.

```ddn
공 := (중심=차림[가로,세로],반지름=크기) 표준장면.원.
```

예상: 중심과 반지름을 종이에 표시하세요. 한 마디 실행 후 `2`, `1`, `0.5`와 원을 비교합니다. 다시 실행해도 이 원은 그대로입니다.

다음은 [11B 두 칸씩 전진](예제/11B_두칸씩전진.ddn)입니다. 처음 값은 시작할 때 한 번 놓고, 매마디에는 이전 위치에 2를 더합니다.

```ddn
(시작)할때 { 위치 <- 0. 차례 <- 0. }.
(매마디)마다 { 차례 <- 차례 + 1. 위치 <- 위치 + 2. 위치 보여주기. }.
```

| 진행한 마디 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 내 예상 위치 |  |  |  |  |
| 실행 후 확인 |  |  |  |  |

수정: 2를 3으로 바꾸세요. 끝 위치가 화면 범위 안에 들도록 가로 범위의 끝도 14로 바꿉니다. [MOD11 세 칸씩 전진](수정실습/MOD11_세칸씩전진.ddn)이 완성 예시입니다. 한마디 진행과 ▶ 재생은 같은 마디 규칙을 사용합니다. 빠르게 재생한다고 한 마디에 더 많이 움직이지 않습니다.

설명할 질문: 위치를 바꾸는 줄은 무엇인가요? 그림을 다시 계산하는 줄은 무엇인가요? 이 두 줄의 역할을 구분해 말하세요.

## 12차시 - 보기값 셈씨와 장면

목표: 계산 결과인 수를 장면으로 바꾸고, 보기값 셈씨의 결과 이름을 설명합니다.

[12A 계산한 크기](예제/12A_계산한크기.ddn)의 `배율반지름:수:셈씨`는 수를 돌려줍니다. `크기그림:보기값:셈씨`는 원과 좌표 범위를 묶은 보기를 돌려줍니다. 두 셈씨를 순서대로 연결합니다.

```ddn
(기본반지름:수,배율:수) 배율반지름:수:셈씨 := {
  배율반지름 <- 기본반지름 * 배율.
}.
반지름 <- (기본반지름=0.5,배율=3) 배율반지름.
```

예상: 0.5의 3배는 얼마인가요? 반지름이 커지면 넓이는 같은 배율로 커질까요? 원문은 반지름을 바꿉니다. 넓이 계산까지 했다고 주장하지 않습니다. 한 마디 실행해 `1.5`와 중심 `(0,0)`의 원을 확인하세요.

[12B 삼각형 넓이](예제/12B_삼각형넓이.ddn)는 `(밑변=6,높이=4)`를 넓이 계산과 그림 계산에 각각 전달합니다. 꼭짓점은 `(0,0)`, `(6,0)`, `(0,4)`입니다. 밑변과 높이를 직사각형으로 그린 뒤 넓이가 그 절반임을 설명하세요. 예상 넓이를 적고 실행 출력 `12`와 비교합니다.

수정: 12A에서 배율을 4로 바꿉니다. 원의 중심도 움직일까요? [MOD12 배율 네 배](수정실습/MOD12_배율네배.ddn)와 비교하세요. 반지름은 2가 되고 중심은 그대로입니다.

설명할 질문: `수`와 `보기값`이 다른 까닭은 무엇인가요? `표준장면.평면`에 요소들과 범위를 함께 주는 이유를 말하세요. 계산만 고치고 그림에 옛 숫자를 남기면 둘이 어긋납니다.

## 13차시 - 보개짜임

목표: 여러 보기가 어떤 관계로 함께 나타나는지 원문으로 표현합니다.

[13A 겹쳐 비교](예제/13A_겹쳐비교.ddn)는 같은 좌표 범위에 두 원을 놓습니다. 으뜸은 기준 그림, 겹은 그 위에 얹는 비교 그림입니다. 중심 `(-2,0)`과 `(2,0)`의 거리는 4입니다.

```ddn
기준보기 := (보기=((가로=-2) 공그림)) 표준보개.으뜸.
비교보기 := (보기=((가로=2) 공그림),기준=기준보기,순서=1) 표준보개.겹.
두공짜임 := (관계들=차림[기준보기,비교보기]) 표준보개.짜임.
```

예상: 두 원을 각각 종이에 그려 겹쳐 보세요. 어떤 그림이 기준인지 표시합니다. 실행해 위치와 출력 `4`를 확인하세요. 으뜸과 겹의 좌표 범위가 같은지도 원문에서 찾습니다.

[13B 그림과 결과표](예제/13B_그림과결과표.ddn)는 점 `(2,5)`를 으뜸에 그리고, `표준보기.결과표`를 오른쪽 곁에 놓습니다. `보임`은 표에 낼 값을 적고, `보여주기`는 출력 글을 남깁니다. 두 방법을 지우며 비교하지 말고 각 결과가 어디에 나타나는지 확인하세요.

수정: 13A의 비교 원 중심을 2에서 1로 옮기고 출력 거리도 3으로 고칩니다. [MOD13 겹의 자리](수정실습/MOD13_겹의자리.ddn)에 정답이 있습니다. 곁 보기를 닫았다 다시 열어도 계산값이 달라지는지 확인하세요. 화면의 배치는 계산 규칙을 바꾸는 조작이 아닙니다.

설명할 질문: 으뜸·겹·곁은 계산 함수 이름인가요, 보기의 관계인가요? 짜임이 어떤 관계들을 담는지 읽어 주세요.

## 14차시 - 물체 돋

목표: 선택한 물체와 그 물체를 자세히 보여주는 셈씨를 연결합니다.

[14A 공 자세히](예제/14A_공자세히.ddn)는 중심 `(1,2)`, 반지름 0.5인 공을 그립니다. `공대상`은 선택할 물체, `공자세히`는 그 대상을 받아 자세한 보기를 만드는 셈씨입니다.

```ddn
(대상:장면요소값) 공자세히:보기값:셈씨 := {
  // 대상과 안내 글을 장면에 넣고 보기값으로 돌려준다.
  ...
}.
공돋 := (대상=공대상,보기법=공자세히) 표준보개.돋.
```

위 코드는 구조 설명입니다. `...`를 실행 원문에 입력하지 말고 연결된 완전한 파일을 여세요. 예상: 원을 누르면 다른 공이 생길까요, 같은 공의 자세한 보기가 열릴까요? 한 마디 실행하고 으뜸의 공을 누른 뒤 설명과 좌표를 확인합니다.

[14B 움직이는 공 돋](예제/14B_움직이는공돋.ddn)는 매마디 위치가 1씩 증가합니다. 세 마디의 위치를 예상하고, 한마디씩 진행하여 `1`, `2`, `3`을 확인합니다. ▶ 재생 중 선택해 현재 위치가 변하는 모습을 관찰한 다음 Ⅱ로 멈춰 읽으세요. 원문 안의 대상 이름은 그대로여도 현재 중심은 변합니다. 화면에서 선택했음을 표시하는 강조와 자세한 보기를 구분하세요.

수정: 14A의 두 원 정의와 안내 글을 함께 고쳐 중심을 `(-1,2)`로 옮깁니다. [MOD14 대상의 자리](수정실습/MOD14_대상의자리.ddn)와 비교합니다. 그림만 바꾸고 돋 대상을 옛 좌표에 남겨 두면 같은 물체를 가리키지 못합니다.

설명할 질문: 물체 이름과 현재 위치는 왜 따로 생각해야 할까요? 돋을 닫는 것과 작품을 중지하는 것은 어떤 차이가 있나요?

## 15차시 - 논리 입력 작은 게임

목표: 키 이름이 아닌 행동 이름으로 게임 규칙을 정의하고 사건 순서를 읽습니다.

[15A 세 칸 이동 게임](예제/15A_세칸이동게임.ddn)은 위치 1, 점수 0에서 시작합니다. 왼쪽 끝은 0, 오른쪽 끝은 3입니다. 이 작품에서는 위치 3에서 `떨어뜨리기`를 누르면 10점을 얻습니다. 작은 학습 규칙이며 완성된 테트리스 규칙이 아닙니다.

```ddn
사건들 <- () 입력사상.사건들.
사건들마다 {
  { 사건들.종류 == "누름" }이면 {
    // 채널 이름과 현재 위치를 보고 작품의 규칙을 실행한다.
  }.
}.
```

`입력/15A.binding.json`은 이 원문과 입력 계약의 결속입니다. `입력/15A.request.json`에는 다음 여섯 마디가 들어 있습니다. 한 번 누른 뒤 뗀 사건을 같은 마디에 기록했으므로 각 표 행의 끝에는 눌린 키가 없습니다.

| 마디 순서 | 행동 | 예상 위치 | 예상 점수 |
|---|---|---|---|
| 1 | 없음 | 1 | 0 |
| 2 | 오른쪽 | 2 | 0 |
| 3 | 오른쪽 | 3 | 0 |
| 4 | 떨어뜨리기 | 3 | 10 |
| 5 | 왼쪽 | 2 | 10 |
| 6 | 떨어뜨리기 | 2 | 10 |

실제 키보드는 키를 받은 마디가 달라질 수 있습니다. **동일한 마디 입력** 비교에는 동봉 요청 파일을 사용합니다. 자유 조작에서는 으뜸 보개를 누르고 →, Space, ←를 천천히 누르며 규칙을 확인합니다.

[15B 순서가 중요한 게임](예제/15B_순서가중요한게임.ddn)에서 오른쪽은 +2, 회전은 ×3, 다시시작은 0입니다. 같은 마디에서 오른쪽 뒤 회전이면 6, 다음 마디에서 회전 뒤 오른쪽이면 20이 됩니다. 두 사건의 순서를 바꾸면 결과가 왜 달라지는지 식을 쓰세요.

수정: 보상을 20으로 바꾸고 새 실행을 시작합니다. [MOD15 보상 바꾸기](수정실습/MOD15_보상바꾸기.ddn)와 비교하세요. 옛 원문에 결속된 기록 대신 수정본 전용 계약·요청을 사용합니다.

## 16차시 - 기록과 재생

목표: 기록이 저장한 입력 사건을 같은 원문에서 다시 실행하고, 서로 다른 규칙의 결과를 비교합니다.

[16A 누름과 반복 기록](예제/16A_누름과반복기록.ddn)은 오른쪽의 누름과 반복에 각각 1을 더합니다. [16B 같은 입력 다른 규칙](예제/16B_같은입력다른규칙.ddn)은 누름에만 1을 더합니다. 두 요청 파일의 세 마디 입력은 누름 → 반복 → 뗌으로 같습니다.

| 마디 순서 | 사건 | 16A의 이동수 | 16B의 이동수 |
|---|---|---|---|
| 1 | 누름 | 1 | 1 |
| 2 | 반복 | 2 | 1 |
| 3 | 뗌 | 2 | 1 |

예상: 키를 뗄 때 이동수가 늘어날까요? 각 원문에서 사건 종류를 확인하고 이유를 적으세요. 실행해 세 마디를 비교합니다.

자기 조작을 기록할 때에는 으뜸 보개에 초점을 두고 ▶ 또는 한마디로 진행합니다. Ⅱ로 멈춘 뒤 들어온 키 사건을 다음 마디에 반영하여 대기 입력이 없게 하고 **논리 입력 기록 저장**을 누릅니다. **봉인 논리 입력 파일 재생**에서 저장한 파일을 열어 같은 원문·같은 계약으로 재생하세요. 편집 칸으로 초점이 옮겨져 입력을 잃었다는 오류가 나면 새 세션으로 시작합니다. 입력 손실을 임의의 뗌 사건으로 덮지 않습니다.

수정: 16B의 한 번 이동량을 2로 고칩니다. [MOD16 같은 기록 두 칸](수정실습/MOD16_같은기록두칸.ddn)의 출력은 `2`, `2`, `2`입니다. **사건 목록이 같다**는 것과 **이미 봉인한 파일을 다른 원문에서 재생할 수 있다**는 것은 다릅니다. 수정 원문에 맞는 계약으로 같은 사건을 새로 기록하세요.

마무리: 예제 하나를 골라 예상값, 실제 출력, 고친 줄, 새 결과를 네 칸에 적습니다. 다른 사람에게 원문과 입력 계약을 함께 전달하고 같은 결과가 나오는지 확인하세요. 이 전달은 수업 활동이며 외부 공개 승인을 뜻하지 않습니다.
